# Stage 4: 画面一覧（screens.json）

前提: `ai/normalized_cases.json` が検証済み（工程3）。スキーマ: `schemas/screens.schema.json`。

共通設計・採点より前に、案件で扱う画面を**一度だけ**確定させる。後の工程はこの一覧から選ぶ。
- PAGE の `elements` は `screen_id` と一致させる（一覧の画面がPAGEに無い・PAGEに一覧外の画面がある → エラー）。
- AX-01 の `operation_screens` も `screen_id` から選ぶ（一覧外 → エラー）。

## 画面の根拠（basis）
- `inferred`: 項目書の文脈から推定した画面。`refs` に画面が現れる原資料の位置が必要。
- `observed`: 対象サイトの調査結果（`runs/<id>/survey/pages.json`）で確認した画面。`url` に調査で開いたページのURL（パス）を書く。
  調査結果が無い、または `url` が調査で開いたページの形（`template`。`/product_details/{*}` のように2つ目以降は可変）に無いとエラー。
- 自分で対象サイトへアクセスしない。調査結果が無ければ全画面 `inferred` にする。

## 調査結果がある場合（site.access: browsable）
- `survey/pages.json` の各ページ（`template`・`title`・`headings`・`inputs`）を読む。必要なら `snapshot` のファイル（ページ構造）を Grep する。
- 項目書に出てくる画面と調査したページを対応づけ、対応したものは `observed`（`url` は調査したパス）にする。
- 調査で開いたページは、画面として数えるか、`not_counted` に `url` つきで理由（例: 項目書に無い）を書く（漏れは `SURVEY_PAGE_UNREVIEWED` 警告）。
- ログイン後・送信後・注文後にしか出ない画面（登録完了、決済、注文完了など）は調査では開けない。項目書から `inferred` で数える。
- 調査結果と項目書が食い違う（項目書の画面が調査で見つからない、名前が違う）ときは、画面一覧は項目書の手順を優先し、`notes` に違いを書く。

## 画面の数え方（共通基準 BOUND-15 を項目書に当てはめる）
1. **候補を全部拾う。** 手順・期待結果・前提に出る「〜画面」「〜ページ」「〜が表示される（見出し・タイトル）」を拾い、
   `screens` か `not_counted` のどちらかに必ず入れる（無言で捨てない）。
2. **別の画面にする:** 遷移の記述があるもの（「〜ページへ遷移」「〜ページが表示される」「URLが〜になる」「見出し〜が表示される」）、
   別のページ名で呼ばれているもの。登録完了・削除完了・注文完了などの完了画面も、見出しの確認やボタン操作をするなら数える。
   一覧からの絞り込みでも、遷移先が別のページ名・見出しで書かれていれば別の画面（例: ブランド別の商品ページ）。
3. **同じ画面にする（`not_counted`、`merged_into` に統合先）:** 同じ画面内のモーダル・確認ダイアログ・タブ・展開表示、
   遷移の記述が無い絞り込み・並び替え・検索結果の表示。
4. **数えない（`not_counted`、`merged_into: null`）:** 通過するだけの画面（自動リダイレクト、手順にも期待結果にも操作・確認が無い中間画面）、
   対象外の外部サイト。
5. **迷ったら:** 遷移の記述があれば別の画面、無ければ同じ画面。判断を `evidence`（数えない場合は `reason`）に書く。
6. ケースが使わず共通部品だけが操作する画面（例: AUTH が操作するログイン画面）も、項目書に現れれば数える。

## ケースとの対応
- `operated_by`: 項目書の手順で、その画面で入力・クリック・選択するケース。共通部品（FLOW・AUTH・DATA）に委ねるかはここでは考えない
  （委ねた操作を AX-01 で数えないのは採点工程。計上ルール COST-13）。
- `checked_by`: その画面の表示を確認するだけのケース。同じケースを両方に入れない。
- どの画面にも出てこないケースは `CASE_NO_SCREEN` 警告。ケースが操作・確認する画面を一覧に入れる。
- AX-01 の `operation_screens` に、一覧でそのケースの `operated_by` に無い画面を入れると `SCREEN_NOT_OPERATED` 警告。

## ID と記載
- `screen_id` は `PG-` で始める英語名（例 `PG-Login`、`PG-ProductDetail`）。`name` はページ名・見出し。
- `url` は項目書に書かれていれば書く。無ければ null（推測で書かない）。
- 一覧を変えたら、PAGE（`common_design.json`）と AX-01 の `operation_screens` を合わせて直す（下流工程は stale になる）。
