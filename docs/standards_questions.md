## SQ-01 共通部品を呼ぶケースの軸の点数（2026-10-10 起票・回答・反映済み）

**状況:** runs/ の8回の実行のうち7回で、意味レビューが同じ「二重計上の疑い」を指摘した（kind: double_count）。
Skill文書に線引きを書き足しても（コミット d18b098、9934834）再発している。

- 共通の DATA / FIX（ユーザー作成・削除）を使うケースで、AX-05（データ準備・後処理）を一律2点にしている
  （01・03・04・05・06）。
- 共通の FLOW（カート〜注文確定）と同じ操作列を検証するケースで、AX-01（操作手順）を2点にしている（02・03・06）。

**基準の現状:** 次の記載はあるが、「共通部品を呼ぶだけのケースの軸の点数」は書かれていない。
- 判定基準 AX-05 の2点条件「複数レコード、ファイル、ユーザー作成、削除・復元が必要。方法は既知」（判定基準!D6）
- 計上ルール COST-04（ケース固有データの指定・cleanup 呼出しは個別レンジ内、共通の準備機構の開発は別計上）
- FLOW 基準（同じ操作列をケースにも二重実装・計上しない）
- 判定例 EX-04（会員準備を含む → AX-05 2点）、EX-01・EX-03（既存部品を呼ぶだけ → 1点）

**確認したいこと:**
1. ケースが DATA/FIX を呼んでユーザーを作成・削除するとき、ケースの AX-05 は「ユーザー作成が必要」として2点か、
   「既存部品の呼出し＋固有データの指定」として1点か。EX-04 と EX-01・EX-03 のどちらに当たるか。
2. ケース自身の検証対象が FLOW の操作列そのもの（例: 注文確定の検証）のとき、AX-01 はケース固有の画面・分岐だけで数えるか。
3. 上記を判定例として基準Excelに追加できるか。

**暫定の扱い:** 検証器は該当する軸が2点以上のとき、ケース固有に残る作業（`overlap_note`）の記載を求める警告
（`AXIS_COMPONENT_OVERLAP`）を出す。点数そのものは変えない（基準にない規則を作らない）。

### 確認したいことの回答

1. 「既存部品の呼出し＋固有データの指定」として1点とする
2. ケース固有の画面・分岐だけで数える
3. Excelを編集できないので、可能ならあなたが追加していい
