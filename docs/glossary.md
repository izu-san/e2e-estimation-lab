## AI・仕組みの用語

| 用語 | 意味 |
|---|---|
| Claude Code | AnthropicのAIが、ターミナルでファイルを読み書きし、コマンドを実行しながら作業するツール。見積もりの「判断」を担当する |
| Skill | Claude Codeに渡す作業手順書。このリポジトリでは `.claude/skills/estimate-e2e/` にあり、`/estimate-e2e` で呼び出す |
| ハーネス | AIの作業を支える周辺ツール一式。読み取り・検証・計算・出力を行うPythonのプログラム（`src/estimator/`、`scripts/estimator`） |
| CLI | コマンドラインから使う操作の入口。`scripts/estimator <サブコマンド>` |
| サブエージェント | メインのAIとは別の会話で動く、役割を限定したAI。ここでは意味レビュー専用の `estimate-reviewer` |
| 意味レビュー | 見積もりの分け方・採点・二重計上などを、**作成とは別のAI**が読み直して指摘する工程。形式や計算の誤りは機械検証が見つける |
| 機械検証 | プログラムによる自動検査。JSONの形式、IDの実在、根拠の有無、再計算の一致などを確認する。意味の正しさまでは判断しない |
| JSON | 構造化データの書式。AIの判断結果は、この形式のファイルとして保存される |
| スキーマ（JSON Schema） | JSONに書いてよい項目・型・値の定義。違反するとエラーになる。AIが工数などの計算値を書くことも、これで禁止している |
| 保護付き実行（見積もりモード） | AIが書き込めるのを現在のrunだけに制限して実行する方式。通常の開発用セッションとは別 |
| 開発モード | ツールやSkillを改修するための通常のClaude Code。見積もり中には使わない |
| Hook | AIの特定の操作（ファイル編集など）の前後で自動実行される確認処理。保護の補助に使う |
| sandbox | OSの機能で、プロセスのファイル書き込み範囲を制限する仕組み。任意で追加する |
| ハッシュ（SHA-256） | ファイルの内容から計算する指紋。内容が変わると値が変わる。変更の検出と再現性の記録に使う |
| モデル | AIの種類。検証は Sonnet 5.5 で行った。モデルを変えると、判断の傾向が変わる可能性がある |

## 見積もりの考え方

| 用語 | 意味 |
|---|---|
| 基準Excel | 判定基準と仮置き工数を書いた2冊のExcel（`standards/`）。工数の**正本**。個別ケース用と共通部品用がある |
| 個別ケース | テスト項目を整理した、見積もりの単位。5軸で採点して難易度を決める |
| 共通作業（共通部品） | 複数のケースが使う土台の作業。ページオブジェクト、認証、データ準備など。数量×単価で計算する |
| 原項目 | 項目書に書かれていた、元のテスト項目 |
| 整理後ケース | 原項目を、見積もりの単位に分解・統合したもの。件数は原項目と一致しない |
| 構成案 | 見積もりの前提の違い（例: ページオブジェクトありとなし）ごとの案。構成案をまたいで合算しない |
| 下限／標準／上限 | 工数のレンジ。標準は、下限と上限の平均ではなく、基準の値 |
| 人時 | 工数の単位。金額・トークン・AIの実行時間は、人時に換算しない |
| 仮定 | 情報が足りないときに置く前提。必ず記録され、「条件付き」の根拠になる |
| 二重計上 | 同じ作業の工数を、ケースと共通部品の両方に入れてしまうこと。最も注意する誤りの一つ |
| run（ラン） | 1回の見積もり実行と、その成果物一式。`runs/<run_id>/` に保存される |
| 案件マニフェスト | 同じ案件の複数ファイルを指定する、ファイルの一覧（YAML） |
| 案件設定 | 見積もりの前提（自動化ツール、構成、対象外など）を書いたYAML（`config/estimate.yaml`） |
| 読み取り設定（アダプター） | 基準Excelのどこに何が書かれているかを、見出し文字列で指定した設定（`config/standards_adapter.yaml`） |
| 文章フィンガープリント | 基準Excelの文章全体のハッシュ。基準の文章が、承認済みの状態から変わっていないかの確認に使う |
| ルール版 | 計算ロジックの版（`case-rule-2` など）。計算結果が変わる変更をしたら必ず上げる |
| 回帰テスト | 変更前後で、既知の結果が変わっていないかを確認するテスト。基準の「判定例」「判定集計例」を使う |

## 採点（個別ケース）

| 用語 | 意味 |
|---|---|
| 5軸 | 個別ケースの採点軸。各軸を1〜3点で評価する |
| AX-01 操作手順 | 操作の経路の複雑さ。1点は単一の短い経路、2点は複数画面・条件分岐・ダイアログ・ファイル操作、3点は複数ユーザーの協調や複雑な状態遷移。ケース自身が操作する画面で数える（COST-13） |
| AX-02 確認手順 | 結果の確認の複雑さ。1点は文言・値・件数の直接比較、2点は複数画面・データの照合や金額計算、3点は複雑な突合や独自の画像・帳票判定 |
| AX-03 実装手段 | 自動化の手段の難しさ。1点は共通部品とPlaywrightの標準操作で完結、2点は小規模な補助処理や既知のAPI連携、3点は独自連携や技術検証が必要 |
| AX-04 あいまい度 | 仕様のあいまいさ。1点は具体的、2点は軽微な欠落（局所的な仮定で方針が決まる）、3点は主要条件が未確定（方針を決められなければ未採点）。2点以上は「条件付き」になる（RULE-07） |
| AX-05 データ準備・後処理 | データの準備と後片付けの手間。1点は静的データか既存fixtureで足りる、2点は複数レコード・ファイル・ユーザー作成・削除が必要、3点は多段階の状態作成や共有資源の隔離が必要。共通部品を呼ぶだけなら1点（COST-11） |
| 総合難易度 | 5軸の点数から、ツールが機械的に決める。**AIは決めない**。いずれかが3点、または合計がHigh閾値以上でHigh、合計がLow上限以下でLow、残りはMid |
| Low上限／High閾値 | 難易度の境目となる合計点。値は基準Excelにある（この文書には書かない） |
| 根拠（evidence） | 点数の理由となる、項目書のセル位置と基準の参照 |

## 共通作業

| 種別ID | 名称 | 内容 | 計上単位 |
|---|---|---|---|
| BASE | テストプロジェクトの土台 | プロジェクトの初期構成 | 独立したテストプロジェクト1式 |
| AUTH | 認証 | ログインやセッション管理の本体 | 独立した認証方式の1実装 |
| FIX | fixture（フィクスチャ） | 準備と後片付けの順序・範囲の管理 | 独立したライフサイクル1単位 |
| DATA | テストデータ | データの投入・識別・復元の本体 | 独立したデータ構造・状態を扱う1機能 |
| PAGE | ページオブジェクト | 画面ごとの操作・状態取得のまとまり | 独立した責務1単位（画面ごとに数える） |
| COMP | 共通UI部品 | 複数画面で使う共通のUI操作 | 再利用するUI責務1単位 |
| FLOW | 業務フロー | 複数の部品を組み合わせた業務の操作列 | 再利用する業務目的1単位 |
| UTIL | 補助機能 | 単一責務の補助機能 | 補助機能1単位 |
| EXT | 外部連携 | 外部システムとの接続 | 接続契約1単位 |
| RUN | 実行構成 | 実行構成と受入確認 | 合意した実行構成1式 |
| CI | パイプライン | CI環境での実行 | パイプライン1単位 |
| REPORT | レポート | 結果の出力・配信 | 出力形式・配信先1単位 |
| DOC | 手順書 | 利用者向けの手順 | 手順一式 |
| POC | 技術検証 | 技術的な問いの検証 | 問い1単位（時間枠として計上） |

| 用語 | 意味 |
|---|---|
| 数量 | 計上単位に当たる、独立した構成要素の数。ケース数やURL数から機械的には決めない |
| 参照キー | 工数表を引くためのキー。`種別ID\|難易度`（例: `PAGE\|Mid`） |
| 既存流用 | 存在と適合性を確認済みの既存部品を使う場合。新規実装分だけが0になり、確認・組み込みは別に計上する |
| 改修 | 既存部品を変更する場合。変更する責務を明記し、同じ単価表を適用する（根拠のない割引はしない） |
| `depends_on` | 実装・実行上の依存先 |
| `used_by` | その部品を使うケース |
| `integrated_into` | 説明上、どの作業に統合したか（計算には使わない） |
| `cost_owner` | 工数を計上する作業。他の作業が計上先なら、その作業自体は計上しない |

## 状態の言葉

| 項目 | 値 | 意味 |
|---|---|---|
| `difficulty`（難易度） | Low / Mid / High | 5軸の合計などから決まった難易度 |
| | Impossible | 実現不可と確認済み。工数は出さない（0人時とは記録しない） |
| | null | 判断材料が足りず、決められない。工数は出さない |
| `estimate_status` | 確定可能 | 仮定なしで、5軸が確定している |
| | 条件付き | 仮定が成り立つ前提の数字。仮定は一覧で表示される |
| | 要確認 | 情報不足などで算定できない |
| `scope` | 対象内 / 別見積 / 対象外 | 今回の見積もりに含めるか |
| `implementation_kind`（共通作業） | 新規 / 改修 / 既存流用 / 要確認 / 対象外 | 実装の区分 |
| `execution_status` | 処理成功 / 処理失敗 | ツールが正常に動き、再計算も一致したか。見積もりの内容が正しいという意味ではない |
| `estimate_completeness` | 全対象算定 / 一部未算定 | 工数を出せなかった項目が残っていないか |
| `semantic_review_status` | 未実施 | 意味レビューをしていない |
| | AIレビュー済 | 別のAIがレビューした。「自己レビュー」（作成したAI自身の見直し）や「未対応N件」が併記されることがある |
| | 人確認済 | 人がレビューを記録した |
| 算定済み総計 | — | 工数を出せた分だけの合計。一部未算定のとき、案件全体の確定総額ではない |
| 工程の状態 | stale | 上流が変わり、再確認が必要 |
| | modified | 検証後に手で変更された |
| | failed_repair_limit | 修正回数の上限に達した |
| 指摘の対応（`resolution`） | fixed / question / rejected / deferred | 修正した／質問に回した／不採用／保留 |

## 基準Excelのルール番号

基準Excelの各シートにあるルールの番号です。内容は基準Excelが正本です。

| 番号 | 場所 | 内容 |
|---|---|---|
| AX-01〜05 | 個別基準「判定基準」 | 5軸の点数条件 |
| RULE-01〜10 | 個別基準「総合判定」 | 総合難易度と見積もり状態の判定手順。RULE-06が総合難易度、RULE-07が見積もり状態 |
| COST-01〜10 | 個別基準「計上ルール」 | 個別ケースの工数に含むもの、別に計上するもの |
| COST-11〜13 | 同上（PoCで追記・**仮**） | 共通部品を呼ぶケースのAX-05（11）、FLOWを検証するケースのAX-01（12）、AX-01の画面の数え方（13） |
| STD-xxx | 個別基準「利用条件」など | 基準の前提・条件（例: STD-005 標準環境、STD-008 判定例は説明用） |
| OUT-01〜14 | 個別基準「AI出力仕様」 | AIが出力する内容の仕様 |
| GEN-01〜12 | 共通基準「適用設定」 | 適用の前提 |
| COM-01〜16 | 共通基準「判定ルール」 | 共通作業の判定規則（数量、改修、既存流用、Impossibleなど） |
| BOUND-01〜14 | 共通基準「構成と重複防止」 | 部品の境界と二重計上の防止 |
| BOUND-15〜19 | 同上（PoCで追記・**仮**） | PAGEの数え方（15）、COMP（16）、FLOW（17）、RUN（18）、PAGEの難易度（19） |
| H2〜H15 | 共通基準「共通作業基準」 | 種別ごとの計上単位の注記 |
| COMMON-OUT-01〜12 | 共通基準「AI出力仕様」 | 共通作業の出力仕様 |
| EX-01〜12 | 各基準の「判定例」「判定集計例」 | 説明用の例。回帰テストにだけ使い、顧客案件の実績ではない |
| SQ-01〜04 | `docs/standards_questions.md` | 基準の担当者に確認した事項の通し番号 |

**仮ルール（COST-11〜13、BOUND-15〜19）は、PoCのために開発側が仮に決めたものです。基準の担当者が確定するまで、暫定の扱いです。**

## エラー・警告の接頭語

エラーコードの対処は [troubleshooting.md](troubleshooting.md) を参照してください。接頭語の目安は次のとおりです。

| 接頭語・語 | 領域 |
|---|---|
| `SCHEMA` | JSONの形式・型の違反 |
| `SCREEN_` / `PAGE_` / `AX01_` | 画面一覧・PAGE・AX-01の整合 |
| `QUESTION_` | 質問と対象の紐づけ |
| `EVIDENCE_` | 根拠の参照 |
| `RECOMPUTE_` / `RULE_VERSION_` | 再計算の照合 |
| `SOURCE_CHANGED` | 実行開始後の入力・基準・設定の変更 |
| `SURVEY_` | 対象サイト調査 |
| `STANDARDS` / `STD_` | 基準Excelの読み取り・整合 |
